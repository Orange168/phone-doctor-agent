## 〇、一句话设想

> **不要盲目地把手机"伪装成没 root"，而是逆向目标 App 到底检测什么，只针对它真查的维度做对抗；并且从"静态指纹隐藏"升级到"动态行为拟人"——让自动化操作在数据分布上和真人无法区分。**

反检测不是装几个隐藏模块就结束，而是一条 **「环境隐藏（藏得住）→ 检测面逆向（知道对方查什么）→ 行为拟人（操作像人）→ 数据飞轮（越用越像）」** 的持续对抗链。

## 一、核心认知升级（本设想的关键）

### 1.1 从「笼统模拟」到「精准对抗」

| 旧思路（要摒弃） | 新思路（本设想） |
|---|---|
| 把所有能改的指纹都改一遍（传感器、基站、Build…） | **先逆向 App 拿到检测面清单，只伪造它真查的维度** |
| 追求"全面模拟一台正常手机" | 追求"在目标 App 的检测项上 0 检出" |
| 伪造静态值（固定一个假读数） | 伪造**符合真人分布的数据流**（时序 + 关联） |
| 被动隐藏（hook 掉检测函数） | **主动拟真**（让 agent 真的动起来，物理数据天然自洽） |
| 一次配好永久有效 | App 更新会加检测，**持续重新逆向、持续迭代** |

**为什么"全面模拟"反而危险**：伪造一个 App 根本不查的维度，等于人为制造一个"和真实世界不一致"的破绽。多造一个假数据，就多一个可能和其他数据矛盾的点（例如：屏幕亮着但光线传感器恒定为 0）。**精准 > 全面。**

### 1.2 第三方 App 拿不到的数据（不用模拟，别做无用功）

- **基站 Cell ID / 信号强度原始信息**：Android 10+ 权限收紧，普通 App 拿不到。
- **全局触摸事件流**：非 root / 非无障碍服务拿不到别的 App 的触摸。
- 结论：这类维度**不需要花精力伪造**，逆向确认检测面后直接划掉。

## 二、反检测分层模型（L0–L4）

| 层 | 对抗目标 | 手段 | 当前状态（一加 Ace Pro） |
|---|---|---|---|
| **L0 环境基线** | BL 锁 / AVB / SELinux 状态 | Tricky Store 伪造 `verifiedbootstate=green`、`flash.locked=1`、`device_state=locked` | ✅ 已落地 |
| **L1 root 隐藏** | su 二进制 / root 进程 / 内核模块痕迹 | KernelSU（内核态 su，非用户态 Magisk）+ Susfs/PathMask 路径遮罩 | ✅ KernelSU v3.2.5 + PathMask |
| **L2 隐藏层 / 注入痕迹** | Zygisk / Riru / Xposed / Frida / 可疑 App 列表 | Zygisk Next（memfd 匿名注入，不留文件路径）+ HMA 隐藏应用列表 | ✅ ZN 1.5.0 + HMA-OSS |
| **L3 行为拟人** | 点击轨迹 / 频率 / 时序 / 操作习惯 | 内核级触摸注入（随机轨迹+压力+时序）+ 真人数据回放 | ⬜ **待做（核心差异化）** |
| **L4 环境状态 / 传感器** | 加速度/陀螺仪/光线长期不变、屏幕状态 | 内核伪造传感器读数（真实数据回放）+ 高权限状态模拟 | ⬜ 待做（随 L3 推进） |

> **L0–L2 是"藏得住"**（让 App 查不到 root/注入痕迹），Momo/Hunter 验收已过；
> **L3–L4 是"像真人"**（让自动化操作的行为分布无法和真人区分），这是数字分身和普通脚本自动化的本质差别，也是防 AI 替代的私有能力壁垒。

## 三、检测面 → 对抗措施 映射表（抖音为主，持续更新）

逆向方法：`jadx 反编译 + Frida hook 关键检测函数 + AI 辅助分析`，产出"检测面清单"。

| 检测维度 | App 怎么查 | 对抗措施 | 层 |
|---|---|---|---|
| root 痕迹 | su 路径 / `which su` / magisk 进程 / 内核模块 | Susfs 内核隐藏 + PathMask 路径遮罩 | L1 |
| 系统属性 | `Build.*` / debuggable / secure 调试标志 / `ro.boot.*` | resetprop 改 + Tricky Store 伪造 boot 状态 | L0/L1 |
| 文件 / 挂载 | /data/adb、magisk 挂载点、/proc/maps 异常路径 | Susfs 伪造挂载 + Zygisk Next memfd 匿名映射 | L1/L2 |
| 包名 / 进程 | 枚举已装 App（Magisk/KernelSU Manager/Xposed/GG） | HMA 隐藏应用列表（target.txt 精确配置） | L2 |
| 注入痕迹 | 内存里扫 frida-agent / Xposed / Zygisk so | Zygisk Next memfd（maps grep 不到）+ 反内存检测模块 | L2 |
| 传感器异常 | 加速度/陀螺仪/光线长期恒定或无噪声 | 内核伪造读数 = **真人操作时录制的真实传感器流回放** | L4 |
| 屏幕 / 状态 | 屏幕方向 / 亮度 / 前台 App / 亮灭屏 | 高权限模拟 + agent 主动间歇亮屏/切换 | L4 |
| **行为特征** | 点击坐标分布 / 滑动轨迹 / 间隔时序 / 操作路径 | **内核级拟人触摸注入 + 真人数据训练的行为模型** | L3 |

**第三方 App 拿不到（逆向确认后划掉，不模拟）**：基站 Cell ID/信号、全局触摸事件流。

## 四、L3 核心：真人数据采集 → 拟人回放（数据飞轮）

这是把"脚本机器人"变成"数字分身"的关键，也是别人抄不走的私有数据。

```
① 采集（root 后全量）
   ├─ 触摸事件：坐标 / 压力(Pressure) / 触摸面积 / 按下-抬起时序
   ├─ 屏幕状态：方向 / 亮度 / 前台 App / 亮灭屏
   ├─ 传感器：加速度 / 陀螺仪 / 光线（内核层，真实噪声）
   └─ 界面语义：UI 树(uiautomator dump) → 标注"推荐流/发布页/评论区"

② 标注
   界面(截图+UI树) → 语义；操作序列 → 意图
   数据集格式：(界面语义, 操作序列, 时序特征, 传感器流, 结果)

③ 学习
   投喂本地小模型 → 学会"真人在这种界面、这种意图下怎么操作"
   → 输出带人类分布特征的行为（不是固定坐标/固定间隔）

④ 高权限回放
   ├─ 内核级触摸注入（一加内核源码可改 input 子系统，加随机轨迹/压力/时序抖动）
   ├─ 内核伪造传感器读数（真实录制流回放，改驱动）
   └─ 屏幕/前台状态模拟

⑤ 飞轮
   每次执行记录 (screenshot, ui_tree, action, result, error)
   失败分类：界面变化 / 点错 / 风控拦截 / 超时
   → LoRA 微调决策模型 → 命中率↑、行为更像本人
```

### 拟人化的五条原则

1. **精准 > 全面**：只模拟 App 真检测的维度，不伪造它不查的（避免引入不一致）。
2. **数据流 > 单值**：伪造的是"符合真人分布的时序+关联数据"，不是一个静态常量。
3. **关联一致性**：屏幕动、传感器动、行为动要协同（亮屏→光线变化→操作，不能孤立）。
4. **主动拟真 > 被动伪造**：能让 agent 真的动（间歇亮屏、随机切换、真实停顿）就比纯 hook 伪造好——物理数据天然自洽。
5. **持续迭代**：App 更新 → 重新逆向 → 更新检测面清单 → 调整模拟。对抗是长期过程。

## 五、工具链与验收标准

### 5.1 检测工具 = 我们的"测试用例"（用对手的眼光验收自己）

| 工具 | 检测内容 |
|---|---|
| **Momo** | su、Magisk 进程、Zygisk、Xposed、挂载、BL 锁状态、可疑 App 等 20+ 项（综合） |
| **Hunter（猎手）** | root + 隐藏层痕迹（Zygisk/Riru/Magisk 模块/LSPosed）深度检测 |
| **Memory Detector** | Xposed/Frida 等内存 hook 注入痕迹 |
| **AppList Detector** | 设备上可疑 App（Manager/Xposed/GG 助手） |

### 5.2 圈内验收标准

```
设备 root + 隐藏层配好
  → 跑 Momo / Hunter / MemoryDetector / AppListDetector
  → 全部 0 检出（Hunter: "ZYGISK NOT DETECTED - msg: 0"）
  → 隐藏层合格，才可跑真实风控 App
```

> ⚠️ **不要在目标 App 的 HMA 隐藏名单里排除 Momo/Hunter**——它们是验收工具，把它们藏起来等于自欺。

### 5.3 当前已落地栈（一加 Ace Pro，2026-09-02 实测全绿）

| 组件 | 版本 | 作用 |
|---|---|---|
| KernelSU | v3.2.5 (32525) | 内核态 root（LKM 模块） |
| Zygisk Next | 1.5.0 (843) | memfd 匿名注入，不留文件路径 |
| HMA-OSS | oss-166 | 隐藏应用列表 |
| Tricky Store | v6.0.0-235 | AVB/Keybox/boot 状态伪造（L0） |
| PathMask | 2.5.0 | 内核路径遮罩 |
| Violet | v1.4 | 附加隐藏 |
| Automatic_brick_rescue | v221204 | bootloop 自愈（防改模块变砖） |
| Momo / Hunter | 4.4.1 / 6.65 | 验收工具（已过） |

**当前边界**：L0–L2（藏得住）已验收；L3–L4（行为拟人 / 传感器回放）尚未开始，是下一阶段主战场。

## 六、为什么必须是 GKI 设备（选型教训）

- RK3568 是 **kernel 4.19 非 GKI**：官方 KernelSU v1.0+ 放弃非 GKI，v0.9.5 是最后支持版本但**只有纯 su、无隐藏层**；强上 KernelSU Next 社区版实测 **bootloop**（execve 原子上下文睡眠等 3 个已修 bug + 未知剩余）。
- 完整反检测（内核 su + Zygisk 隐藏层）需要 **GKI 5.10+** → 选了一加 Ace Pro（骁龙 8+ Gen1，内核 5.10 GKI，OnePlusOSS 有内核源码可改 input 子系统做 L3）。
- **RK3568 保留做 AOSP 编译 / Perfetto / 内核学习设备**，不承担反检测对抗任务。

## 八、关键风险与合规

| 风险 | 对策 |
|---|---|
| 行为检测被风控标记 | 低频策略 + 人工兜底 + 内核级拟人注入；**单设备单账号**、稳定环境 |
| 改内核/模块变砖 | Automatic_brick_rescue（连续重启 3 次自动禁用模块）+ 全量 update.img 可回滚 |
| KernelSU 升级翻车 | 三件套（内核模块/ksud/Manager）版本锁死，禁止单独升 Manager |
| App 更新加新检测 | 检测面清单纳入定期重新逆向（持续工作，非一次性） |
| **合规** | 只做技术研究 + 个人半自动运营；**不规模化、不碰他人账号、不碰热门游戏反作弊**（root+热门游戏=封号雷区） |

## 九、一句话总结

**反检测的护城河不是"装了多少隐藏模块"，而是"逆向检测面的精准对抗 + 真人行为数据飞轮"。** L0–L2 让手机"藏得住 root"，L3–L4 让自动化"操作得像人"——前者是开源方案能抄的，后者是靠自己设备、自己数据、自己内核改出来的私有能力，这正是防 AI 替代的核心壁垒。
